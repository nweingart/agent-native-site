# Theming & Dark Mode

agent-native uses CSS custom properties for all visual tokens. Override them to match your app's design system.

## Dark mode

Dark mode activates automatically when either `.dark` or `.an-dark` is present on any ancestor element:

<CodeBlock
  code={`<!-- Tailwind convention — works automatically -->
<html class="dark">

<!-- Library's own class -->
<html class="an-dark">

<!-- Both work. Use whichever your app already uses. -->`}
  lang="html"
/>

<Callout variant="info">
  If your app already sets `className="dark"` on `<html>` (the Tailwind convention), agent-native's dark mode works with zero configuration.
</Callout>

## Overriding tokens

Override any token in your CSS to match your brand:

<CodeBlock
  code={`/* Match your app's color scheme */
:root {
  --an-status-running: #6366f1;    /* Indigo instead of blue */
  --an-status-complete: #22c55e;   /* Tailwind green */
  --an-surface-0: #0f172a;        /* Slate-900 */
  --an-surface-1: #1e293b;        /* Slate-800 */
  --an-border-color: #334155;     /* Slate-700 */
  --an-font-sans: 'Inter', sans-serif;
}`}
  lang="css"
  filename="globals.css"
/>

## Layer architecture

All agent-native component styles are wrapped in `@layer agent-native`. This means:

1. Your unlayered CSS automatically wins over library styles
2. Tailwind utilities automatically win (they're unlayered too)
3. No `!important` needed, ever

<CodeBlock
  code={`/* This just works — no specificity issues */
.an-timeline__step {
  border-radius: 12px;
  padding: 12px 16px;
}

/* Tailwind classes on classNames prop also just work */
<AgentTimeline
  classNames={{ step: "rounded-xl px-4 py-3" }}
/>`}
  lang="css"
/>

<Callout variant="tip">
  The `@layer` architecture means you can progressively override styles — start with the defaults, then customize as needed without fighting specificity.
</Callout>
